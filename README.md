# WEG · 世界末日女朋友

> 面向中文读者的**世界模型社区与数据库**。

把世界模型的格局、路线、公司（大厂 / 初创 / 海外 / 学术）、模型、产品、论文、研究者整理清楚，让感兴趣的人一次看懂。

- **中文名**：世界末日女朋友
- **英文全称**：World's End Girlfriend
- **缩写**：WEG
- **线上**：https://weg.inon.space

---

## 这是什么

世界模型（World Model）是当下 AI 最热也最含混的赛道之一——至少四拨人（AGI 认知派、具身训练派、科学模拟派、可交互内容生成派）在共用同一个名字，彼此的技术路线、评估方式、目标产品都不一样。

WEG 要做的是**把这件事讲清楚**：

1. **数据库** —— 机构 / 人物 / 模型·产品 / 论文 / 概念·路线 / 基准·榜单，每条都带出处和可信度标记
2. **文章** —— 对领域的判断、分类法、取舍，署名且主观
3. **动态** —— 按时间倒序，复用实体表，不单独维护

**多平台**：公众号（长文）、小红书（长文，零导流动作）、推特（中文短意见）。网站是家，平台是入口。

## 设计原则

| 原则 | 含义 |
|---|---|
| **可溯源优先于「全」** | AI 时代「全」不是差异化，**每条都有出处、标可信度**才是 |
| **分类法是视图，不是表结构** | 底层只存客观事实，分类法叠在上面——改分类不用迁数据 |
| **多种划法并列展示** | 不自己划一刀排除谁；把「这个领域有几种分法」本身作为内容 |
| **文章是引擎，数据库是副产品** | 先写文章，让数据库从文章里长出来，而不是先建空库 |
| **少开表、多用字段** | 模型与产品同表用 `kind` 区分；文章/播客/视频同表用 `kind` 区分 |
| **前期不做社区** | 无登录、无评论、无投稿 |
